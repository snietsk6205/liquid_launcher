# Decisions

Choices made without asking, newest at the bottom. Each one says what was chosen, why, and what it would cost to reverse. Items marked **(open)** have a matching question in `docs/07-questions.md`; they are reversible until the phase named.

| # | Date | Decision | Why | Cost to reverse |
|---|---|---|---|---|
| D1 | 2026-11-12 | Design docs live in `docs/` as Markdown, numbered 01–07 to match the seven requested deliverables. | Readable on the phone in GitHub, versioned with the code. | None |
| D2 | 2026-11-12 | The redirect service subscribes to accessibility events from HONOR Home and from the launcher only; content-change events only while HONOR Home is in front. | Battery: no wake-ups while you are in other apps. | Low |
| D3 | 2026-11-12 | Recents detection is data-driven (id list, id substring, class names) with a calibration wizard, instead of one hard-coded view id. | Survives MagicOS renaming ids. | Low |
| D4 | 2026-11-12 | A loop guard pauses the engine after 4 redirects in 3 seconds. | The worst possible failure is a phone where recents cannot be opened. | Low |
| D5 | 2026-11-12 | Launcher activity is `singleTask`, excluded from recents, launched with no window animation; the launcher animates its own content in. **(open, Q1)** assumes HONOR Home's home screen is empty. | Hot start in a few frames, hand-over looks like plain wallpaper. | Low |
| D6 | 2026-11-12 | The launcher draws the wallpaper itself ("launcher-managed" mode) by default. **(open, Q2)** | The glass library can only refract content drawn by the app, and since Android 13 (the phone runs 15) apps cannot read the system wallpaper. | Medium: other modes exist as settings, but glass quality differs |
| D7 | 2026-11-12 | Screen-off trigger defaults to "always", 1000 ms, matching the existing macro. **(open, Q3)** | Replicate current behaviour first. | None (setting) |
| D8 | 2026-11-12 | Glass has three quality tiers (Full / Frosted / Tint) with automatic step-down, and is never applied per item in scrolling lists. | 90 Hz on a Dimensity 6020 is the main performance risk. | Low |
| D9 | 2026-11-12 | Deep shortcuts are replaced by static-manifest shortcuts, legacy shortcut providers, an activity picker and notification actions. No Shizuku. | Shizuku needs re-pairing after each reboot, which costs your time. | Low: can be added as an optional module |
| D10 | 2026-11-12 | All options are declared in one settings registry; settings UI, search, reset, presets, profiles and export are generated from it. | Hundreds of options stay maintainable and consistent. | High after Phase 1B, so it is built first |
| D11 | 2026-11-12 | Storage: settings in DataStore, layout / tags / usage / study cache in Room. Themes are versioned JSON (`.lltheme`, a zip with assets); backups are `.llbackup` zips with optional passphrase. | Typed, fast, exportable. | Medium |
| D12 | 2026-11-12 | Tasks sync uses two files with one writer each (`plan.json` by Claude, `state.json` by the launcher) in a separate private repo. | Removes merge conflicts; keeps the phone's token away from the source repo. | Low before Phase 5 |
| D13 | 2026-11-12 | Study mode is implemented as a profile switch, not as a separate feature. Friction stays separate. | One mechanism for layouts; fewer special cases. | Low |
| D14 | 2026-11-12 | Mindful friction applies to launches from the launcher only by default. **(open, Q17)** | Catching launches from recents needs events from all apps, which costs battery. | None (setting) |
| D15 | 2026-11-12 | Phase 1 is delivered as 1A (redirect engine + device diagnostics) and 1B (MVP). | Four device behaviours decide the architecture; a ten-minute test settles them before weeks of work. | None |
| D16 | 2026-11-12 | minSdk 33, targetSdk 33, compileSdk latest. | Matches the device; avoids behaviour changes that bring no benefit to a sideloaded app. Raised only for a concrete reason. | Low |
| D17 | 2026-11-12 | Gradle modules: `app`, `core/{common,model,settings,data,designsystem,icons,search,platform}`, `feature/{redirect,home,drawer,search,widgets,study,settings}`, `baselineprofile`. Core logic modules avoid `android.*` where possible so they test on a plain JVM. | Build speed, testability; mirrors the layering used by wmkeyboard. | Medium |
| D18 | 2026-11-12 | No DI framework: constructor injection with a small hand-written app graph. KSP only for Room. | Faster builds and startup; the object graph is small. | Medium |
| D19 | 2026-11-12 | Signing key committed to this private repo; APKs published as GitHub Releases. **(open, Q18, Q20)** | Every build installs over the previous one with no action from you. Must be rotated if the repo ever becomes public. | Low: a new key means one reinstall |
| D20 | 2026-11-12 | App name "Liquid Launcher", package `dev.liquid.launcher`. **(open, Q19)** | Needed for Phase 1A. | High after first install (reinstall, settings lost unless backed up) |
| D21 | 2026-11-12 | Network use is limited to GitHub sync, the updater and (opt-in) weather. No analytics, no crash reporting service; crashes go to the local debug log. | Offline-first, privacy. | None |
| D22 | 2026-11-12 | English UI first, all strings in resources. **(open, Q15)** | Fastest path; translation stays possible. | Low |
| D23 | 2026-11-12 | Default delay after the system launcher appears is 50 ms, not 0 as first written in the settings tree. Recents is checked again when the delay ends. | A redirect that fires while recents is still opening would break recents, which is far worse than 50 ms more of plain wallpaper. Lower it in settings once the debug log shows it is safe on the phone. | None (setting) |
| D24 | 2026-11-12 | The system launcher is detected automatically (the phone's default launcher) and its home activities are looked up from the package, instead of hard-coding `com.hihonor.android.launcher` and `DrawerLauncher`. Both can still be set by hand. | Survives a MagicOS update or a switch between drawer and standard style, and lets CI test the redirect against the AOSP launcher on an emulator. | None |
| D25 | 2026-11-12 | Every build is tested on an emulator (Android 13 at first, Android 14 since D35) in GitHub Actions before a release is published: home redirects, recents is left alone, leaving recents redirects, screen off pre-positions, settings screens open, no crash. | I cannot run Android builds or a device in my own environment, and a broken APK would cost your study time. The AOSP launcher has the same QuickStep base as HONOR Home. | None |
| D26 | 2026-11-12 | In Phase 1A, UI text is written inline in Kotlin (option titles live in the settings registry). This revises D22; moving text to string resources is mechanical and happens before any translation. | Speed, and option text stays next to the option's declaration. | Low |
| D27 | 2026-11-12 | Releases are tagged `v<versionName>`; newer builds of the same version replace the APK in that release. `versionCode` is the CI run number. | One stable link per phase, and every build installs over the previous one. | None |
| D28 | 2026-11-12 | The home screen in Phase 1A is temporary (clock, all apps, glass bar). The real grid, drawer and search are Phase 1B. | Phase 1A exists to prove the redirect and measure the device. | None |
| D29 | 2026-11-12 | Revises D2: the service stays subscribed to the system launcher's window and content events all the time, instead of switching content events on and off. It still receives nothing from any other app. | The switch is a system call that sat in the redirect path (128 ms on the emulator). While the engine is idle these events are dropped immediately, so the cost is negligible. | Low |
| D30 | 2026-11-12 | After a system launcher event that cannot be matched to the screen yet, the engine keeps checking for 30 seconds (every 80 ms for 1.5 s, then at the poll interval). | Android shows the previous app "live" inside recents, so the system launcher may only become the active window later, without a new event. | Low |
| D31 | 2026-11-13 | (Opus) Home defaults: 5 × 9 grid, a 3-row clock across the top, no labels, pill = search field + date, long press on empty space = edit mode, double tap = lock, long press on the pill = settings. | Matches the user's current layout; settings no longer has a permanent pill slot (feedback 1). | None (settings) |
| D32 | 2026-11-13 | (Opus) The app drawer is always composed and slid off screen while closed. | No first-frame stall when opening; a drag started in the drawer survives it closing. | Low |
| D33 | 2026-11-13 | (Opus) Settings previews: the settings module exposes a `SettingsPreviews` hook; the app wires it to a scaled, touch-blocked copy of the real home screen. | Live preview without the settings module depending on the home module. | Low |
| D34 | 2026-11-13 | (Opus) Home pressed on the launcher = the redirect brought it back within 1.5 s of pausing and no app was started in between. | Home always passes through the system launcher first, so the activity is never resumed when the intent arrives. | Low |
| D35 | 2026-11-13 | (Opus) Emulator test back on API 34 (was 35, D25 note). | The API 35 image refuses to enable the accessibility service from adb, so the redirect could not be tested there. The phone itself (API 35) works. | None |
| D36 | 2026-11-13 | (Opus) The phone runs Android 15 (API 35), not 13. Docs corrected; minSdk and targetSdk stay 33 (D16). | Nothing in the plan needs API 35 APIs; targetSdk 35 would only add enforced behaviour. Private space apps stay invisible (launcher role needed). | None |
| D37 | 2026-11-13 | (Opus) Leaving recents redirects only when the system launcher's home screen (workspace + hotseat) or its own drawer is visible, with no fallback timer. Drawer ids are a new detection setting. | 0.2.0 redirected over apps opened from recents, including the app-lock screen. | None (setting "Only redirect over the home screen or drawer") |
| D38 | 2026-11-13 | (Opus) If recents opens within 600 ms of a redirect and the launcher then covers it, recents is opened again once (global action), at most once per 5 s. | On the phone the home screen views are visible during a recents gesture too, so no signal tells a slow recents swipe from going home in time; recovery is reliable where prediction is not. | None (setting) |
| D39 | 2026-11-13 | (Opus) Nothing slow runs on the redirect thread: the split-screen check uses a value read on a side thread, and the "tree" log level walks windows on that side thread. | The log showed a 3.2 s redirect (window list call) and redirects fired after the user had already opened an app (tree walk of the app's window). | Low |
| D40 | 2026-11-13 | (Opus) Drawer default transition "depth": home shrinks and blurs, the drawer rises 12 %, the bottom pill turns into the search field; springs take the finger's speed. | D41 | 2026-11-13 | (Opus) Home layout stores the home page by page id; clock options moved to their own "Clock" settings section (keys unchanged). | Page reorder keeps the home page; the clock is reachable from its edit-mode frame. | Low |
